1. Proje Tanıtımı

Taskora, yazılım ekiplerinin görevlerini merkezi bir servis üzerinden oluşturması, çalışanlara ataması, durum ve öncelik bilgilerini takip etmesi için tasarlanmış bir görev yönetim platformudur. Bu doküman Taskora'nın Node.js ve Express.js ile geliştirilen backend modülünü kapsar.

Backend eğitim sürümü tamamen REST API mantığında çalışır. Veriler eğitim kapsamına uygun olarak yerel bir JSON dosyasında tutulur. Taskora Web, Taskora Database ve Taskora Mobile ayrı eğitim teslimleridir; bu sürümde backend ile doğrudan entegre değildir.

1.1 Amaç

Projenin amacı; Node.js çalışma ortamı, Express.js sunucusu, routing, middleware, CRUD işlemleri, HTTP durum kodları ve JSON veri yönetimi konularını gerçek hayata yakın tek bir senaryoda uygulamaktır.

1.2 Problem ve çözüm

Bir ekipte görevlerin kime atandığı, hangi aşamada olduğu ve hangi önceliğe sahip olduğu düzenli tutulmadığında iş takibi zorlaşır. Taskora Backend her görev için başlık, açıklama, durum, öncelik, sorumlu, proje ve zaman bilgilerini tek biçimde saklar ve istemcilere beş temel CRUD endpointi sunar.

1.3 Proje kapsamı

  • Yeni görev oluşturma
  • Tüm görevleri listeleme ve isteğe bağlı filtreleme
  • ID ile görev detayı görüntüleme
  • Görevin seçilen alanlarını güncelleme
  • Görev silme
  • Tüm istekleri logger middleware ile terminale yazma
  • JSON dosyasına kalıcı kayıt ve açıklayıcı hata cevapları

3. Mimari ve İstek Akışı

HTTP İstemcisi / Postman │ ▼ Express Uygulaması (app.js) │ ├──► Logger Middleware │ ▼ Task Router (/tasks) │ ▼ Task Controller │ ▼ src/data/tasks.json

app.js Express uygulamasını kurar, logger ve JSON body middleware'lerini ekler, /tasks yolunu task router'a bağlar ve merkezi 404/500 hata cevaplarını tanımlar. Router HTTP methodunu ilgili controller fonksiyonuna yönlendirir. Controller veriyi okuyup doğrular, işlemi gerçekleştirir ve JSON cevap döndürür.

5.1 POST /tasks

title, status, priority ve assignee alanları zorunludur. Başarılı işlem yeni görevi, sunucunun ürettiği ID ve zaman alanlarıyla birlikte döndürür.

POST /tasks
Content-Type: application/json

{
  "title": "Postman API testi",
  "description": "CRUD isteklerini kontrol et",
  "status": "pending",
  "priority": "high",
  "assignee": "Yiğit Kaan Bilir",
  "projectId": 1
}

5.2 GET /tasks ve filtreleme

Temel istek bütün görevleri JSON dizisi olarak döndürür. İsteğe bağlı ileri seviye özellik olarak durum ve öncelik filtreleri birlikte veya ayrı kullanılabilir.

GET /tasks
GET /tasks?status=completed
GET /tasks?priority=high
GET /tasks?status=in_progress&priority=medium

5.3 GET /tasks/:id

Pozitif tam sayı biçimindeki ID ile tek görev döndürülür. Geçersiz ID biçimi 400, bulunmayan görev 404 üretir.

5.4 PUT /tasks/:id

İstemci yalnızca değiştirmek istediği alanları gönderir. id, createdAt ve updatedAt istemci tarafından değiştirilemez. Başarılı güncellemede updatedAt yenilenir.

{
  "status": "in_progress",
  "priority": "medium"
}

5.5 DELETE /tasks/:id

Görev JSON dizisinden çıkarılır ve veri dosyası güncellenir.

{ "message": "Görev başarıyla silindi." }

6.2 Doğrulamalar

  • İstek gövdesi JSON nesnesi olmalıdır.
  • Oluşturmada zorunlu alanlar bulunmalıdır.
  • Başlık ve sorumlu boş metin olamaz.
  • Durum ve öncelik yalnızca tanımlı değerlerden biri olabilir.
  • projectId gönderilirse pozitif tam sayı olmalıdır.
  • Güncellemede en az bir düzenlenebilir alan bulunmalıdır.
  • Tanımlanmayan veya sunucuya ait alanlar değiştirilemez.

7. JSON Veri Yönetimi

Controller her işlemde src/data/tasks.json dosyasını UTF-8 olarak okur ve içeriğin dizi olduğunu doğrular. Yazma işlemi önce süreç ID'sini içeren geçici bir dosyaya yapılır, ardından dosya yeniden adlandırılarak asıl veri dosyasının yerini alır. Böylece yarım yazılmış JSON bırakma riski azaltılır.

Yeni ID, mevcut en yüksek ID'nin bir fazlasıdır. Oluşturma, güncelleme ve silme işlemleri dosyaya yazıldığı için sunucu kapatılıp açıldığında görev değişiklikleri korunur.

Bu teslimde veritabanı veya authentication bulunmaz. JSON dosyası eğitim kapsamındaki veri yönetimi gereksinimini karşılar. TaskoraDB entegrasyonu sonraki geliştirme aşamasıdır.

8. Test Planı ve Doğrulama

8.1 Zorunlu Postman akışı

  1. POST /tasks: Görev oluşturulur; 201 Created.
  2. GET /tasks: Yeni kayıt listede görülür; 200 OK.
  3. GET /tasks/:id: Doğru görev döner; 200 OK.
  4. PUT /tasks/:id: Durum ve öncelik değişir; 200 OK.
  5. DELETE /tasks/:id: Görev silinir; 200 OK.

Hazır Postman koleksiyonu ilk cevaptaki ID'yi koleksiyon değişkenine kaydeder. Böylece detay, güncelleme ve silme istekleri aynı kaydı kullanır. Her zorunlu istekte method, URL, HTTP status ve response JSON görünür şekilde ekran görüntüsü alınır.
